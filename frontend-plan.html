Workhub Frontend Plan

Architecture and implementation roadmap for the Personal Client Outreach & Proposal CRM.

Overview

Workhub is a personal CRM for a solo creative professional managing weekly outreach cycles, prospect ranking, email personalization, proposal building, and a deal pipeline. The frontend is an Inertia v3 single-page application: React 19 + TypeScript + Tailwind 4 + shadcn/ui (new-york, neutral). Routes are typed via Wayfinder. The app shell is a collapsible sidebar with 11 navigation sections.

Design language Instrument Sans for UI, oklch neutral tokens for theming, shadcn/ui new-york (smaller radii, tighter spacing). All custom components use semantic token classes (bg-background, text-foreground, bg-card) — never raw colors. The neutral palette carries no chromatic bias.

Today's Outreach Card Structure

Each assignment card in the Today's Outreach list renders:

  • Company — name + initials avatar (color from company hash)
  • Contact — full name + job title
  • Status chip — mapped from ContactStatus: New (blue), Researched (gray), Contacted (amber), Interested (green), Not Interested (red)
  • Last contact — "X days ago" or "Never contacted" in muted text
  • Opportunity — linked opportunity title + amount (if exists)
  • Suggested service — bolded service name from assignment
  • Angle — the personalized reason/suggested pitch from assignment snapshot
  • Actions — [Draft Email] opens composer sheet, [Skip] marks skipped (optimistic)

Data Flow

The DashboardController@index resolves these Inertia props:

PropSourceDeferred?
todayOutreachOutreachAssignment::where('assigned_on', today)->with('contact.company','suggestedService')->orderBy('rank')No — loads first
nextBestProspectsContact::bestFirst()->contactable()->limit(10)->with('company')Yes
followUpsFollowUp::pending()->where('due_on', '<=', today)->with('contact.company')No
pipelineSummaryOpportunity::selectRaw('stage, count(*), coalesce(sum(amount),0)')->groupBy('stage')Yes

Carbon mutation trap When computing date ranges for queries, always ->copy() before calling startOfDay(), addDays(), etc. Carbon mutates in place; shared references corrupt other queries.

Implementation

// resources/js/components/command-palette.tsx
// Uses shadcn/ui Command (cmdk) + global Cmd+K listener

import { Command } from 'cmdk';
import { Dialog } from '@/components/ui/dialog';

export function CommandPalette() {
  const [open, setOpen] = useState(false);

  useEffect(() => {
    const handleKeyDown = (e: KeyboardEvent) => {
      if (e.key === 'k' && (e.metaKey || e.ctrlKey)) {
        e.preventDefault();
        setOpen(prev => !prev);
      }
    };
    document.addEventListener('keydown', handleKeyDown);
    return () => document.removeEventListener('keydown', handleKeyDown);
  }, []);

  return (
    <Dialog open={open} onOpenChange={setOpen}>
      <Command>
        <Command.Input placeholder="Search or jump to..." />
        <Command.List>
          <Command.Group heading="Navigate">...</Command.Group>
          <Command.Group heading="Actions">...</Command.Group>
        </Command.List>
      </Command>
    </Dialog>
  );
}

Dark Mode Strategy

Already wired: use-appearance.tsx toggles the .dark class on <html>, and initializeTheme() runs on load. The oklch token system in app.css defines complete palettes for both themes.

Rules for New Components

  • Always use semantic tokens: bg-background, text-foreground, bg-card, text-muted-foreground, border-border, bg-accent. Never hardcode bg-white, text-gray-500, or dark:bg-neutral-800.
  • Charts: Use chart-1 through chart-5 — they're defined for both themes.
  • Status colors: The StatusBadge component should use a lookup map that maps each status to its semantic color, not inline classes.
  • Migration note: app-header.tsx uses raw dark:bg-neutral-800 / dark:stroke-neutral-100/20 — these should migrate to token-based classes during Phase 12 polish.

Table Responsiveness

The DataTable component should accept a responsive column config: below md, hide secondary columns (last-contacted, score, tags, budget) and show as a card list. The primary column (name + company) is always visible. On desktop, show the full table.

State Management

Workhub is server-driven. Most state lives in Inertia page props. No global client store (Redux, Zustand) is needed.

Patterns

PatternUse CaseInertia v3 API
Server propsAll data display (lists, details, stats)Inertia::render() with eager-loaded relations
Deferred propsHeavy dashboard sections (next best prospects, pipeline summary, goal)Inertia::defer() + skeleton fallback
Optimistic updatesQuick actions: skip assignment, mark contacted, snoozerouter.visit() with preserveScroll: true
PollingEmail open/reply status, dashboard refreshusePoll(interval, url, { preserveState: true })
URL-driven filtersSearch, status filter, date range — persisted in query paramsrouter.get(url, filters, { preserveState: true })
Local state onlyCommand palette, modal open/close, sidebar collapseuseState / SidebarProvider

Forms

Use Inertia's useForm for forms that submit to Inertia routes (create/edit contact, create proposal). For standalone API calls (AI draft generation, email send via third-party), use Inertia v3's useHttp hook or the built-in XHR client with interceptors.

Toasts

Server-side flash messages route through useFlashToast → Sonner. Client-side actions call toast.success() / toast.error() directly. Never mix the two — pick one path per action.

Implementation Phases

Each phase produces a shippable slice. Dependencies flow downward — a later phase can start once its direct prerequisites are done, but need not wait for everything above it.

Phase 1 — Foundation Pass

Install missing shadcn/ui components. Create TypeScript types for all 23 enums and 12+ models. Build shared components: PageLayout, DataTable, EmptyState, LoadingSkeleton, StatCard, StatusBadge, TemperatureBadge, SearchInput, ConfirmDialog, DateRangePicker. Update app-sidebar.tsx with all 11 nav items grouped. Define all routes in routes/web.php. Generate Wayfinder. Add command palette shell to app.tsx.

Phase 2 — Dashboard

DashboardController with real data queries. Today's Outreach list + AssignmentCard. Next Best Prospects ranking. Pipeline Summary stat cards. Monthly Goal progress bar. Follow-ups due/overdue sidebar. Deferred props for heavy sections.

Phase 3 — Prospects

Index page with DataTable (search, filter, sort, paginate). ProspectFilters component. Show page with tabs: overview, emails, activities, proposals. ActivityTimeline on show. Create/Edit via Sheet (slide-in form).

Phase 4 — Companies

Index with card grid + table toggle. Show page: contacts list, opportunities, research notes. Create/Edit via Sheet. Company research fields (description, what_they_do, opportunities, suggested_pitch).

Phase 5 — Outreach

Today's queue view (the main outreach screen). DraftEmailComposer: template selection → variable interpolation → preview → send. Mark contacted, skip, snooze actions with optimistic updates. Cycle history list. Cycle detail view with all assignments.

Phase 6 — Follow-ups

Grouped list: overdue (red), today (amber), upcoming (muted). Quick-complete and reschedule actions. Link to contact detail. Optional: link to outreach assignment if follow-up originated from one.

Phase 7 — Pipeline

Kanban board with drag-and-drop (@dnd-kit). OpportunityCard with amount, contact, company, stage. Stage column totals (count + MWK sum). Drag between columns to change stage. New opportunity creation.

Phase 8 — Proposals

Index with status filters. Show with version history, view tracking, amounts. ProposalBuilder: section editor with template loading, line items editor. PDF export trigger (POST → download). Send proposal action.

Phase 9 — Clients + Projects

Client index (active / former / retainer filters). Client detail: projects list, revenue summary, linked contact. Project status tracking. Link from won opportunities.

Phase 10 — Templates

Email template list + editor (with variable reference sidebar). Proposal template list + section editor. Template preview. Default template marking.

Phase 11 — Analytics

Outreach performance: sent / opened / replied / converted rates. Conversion funnel visualization. Revenue tracking in MWK. Time-based charts: weekly outreach, monthly revenue, pipeline velocity. Date range picker integration.

Phase 12 — Polish

Dark mode audit across all pages — no raw colors, all tokens. Responsive audit (mobile, tablet, desktop). Empty states for every page. Loading skeletons for every data-heavy page. Validation error states for all forms. Keyboard navigation for command palette and kanban. Performance: deferred props, prefetching on hover, lazy-loaded charts.
